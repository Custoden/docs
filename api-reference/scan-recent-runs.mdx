---
title: "Scan recent workflow runs"
openapi: "GET /v1/github/repos/{owner}/{repo}/runs"
description: "Analyzes the workflows that actually ran in a public repository, not just the ones on the default branch."
---

Attackers who steal a token often push a workflow that sends secrets to their server, let it run once, then revert the commit or force-push over it. The file disappears from the repository, but the run stays in the Actions tab. This endpoint takes each recent run, fetches the workflow file at the exact commit it ran, analyzes it, and checks whether that commit is still part of its branch.

Costs 10 units of your [rate limit](/getting-started/rate-limits).

## Path parameters

| Name | Type | Description |
|---|---|---|
| `owner` | string | Repository owner |
| `repo` | string | Repository name |

## Query parameters

| Name | Type | Description |
|---|---|---|
| `limit` | integer | Runs to scan, newest first. 1 to 50, default 30 |

## Example

```bash
curl "https://api.custoden.com/v1/github/repos/acme/app/runs?limit=20"
```

## Response

| Field | Type | Description |
|---|---|---|
| `repository` | object | `full_name`, `default_branch` and `url` |
| `runs_scanned` | integer | Runs returned by GitHub |
| `summary` | object | Count of findings per severity, plus `total` |
| `findings` | array | Findings across all workflow versions that ran, sorted by severity |
| `runs` | array | One entry per run |
| `checks.branch_history` | object | How many branch and commit pairs were checked for force-pushes |
| `checked_at` | string | ISO 8601 timestamp |

### Finding

Same fields as [workflow findings](/api-reference/analyze-a-workflow#finding), plus:

| Field | Type | Description |
|---|---|---|
| `workflow.path` | string | Workflow file that ran |
| `workflow.commit` | string | Commit the run used |
| `workflow.state` | string | See `workflow_state` below |
| `runs` | integer[] | IDs of runs that used this workflow version |

For workflow versions that still match the default branch, only `high` and `critical` findings are included. Use [Analyze a workflow](/api-reference/analyze-a-workflow) for the full hardening report on current files.

### Run

| Field | Description |
|---|---|
| `workflow_state` | `current` (identical to the default branch), `modified` (differs from it), `removed` (not on the default branch), `dynamic` (GitHub-managed, such as CodeQL default setup) or `unavailable` (file could not be fetched) |
| `commit_state` | `on_branch`, `rewritten` (commit is no longer in the branch history), `branch_deleted` or `not_checked` |
| `from_fork` | The run used code from a fork, as in pull requests from forks |
| `findings` | Number of findings linked to this run |

Branch deletion after a merged pull request is normal, so `branch_deleted` alone does not produce a finding.

## Rules specific to runs

| Rule | Severity | Meaning |
|---|---|---|
| `workflow-removed-after-run` | high, medium or low | The workflow version that ran is not on the default branch. High when that version has high or critical findings, medium when it had access to secrets |
| `run-commit-rewritten` | high on the default branch, otherwise medium or low | The commit that ran was removed from its branch by a force-push |
| `campaign-workflow-file` | critical or medium | The file name matches one used by a known campaign, such as `shai-hulud-workflow.yml` |
| `campaign-branch` | critical | The run happened on a branch named after Shai-Hulud |

## Errors

| Status | Code | When |
|---|---|---|
| 400 | `invalid_repository` | Owner or repository is not a valid GitHub name |
| 400 | `invalid_limit` | `limit` is not an integer from 1 to 50 |
| 404 | `repository_not_found` | Repository does not exist or is private |
| 429 | `rate_limited` | See [Rate limits](/getting-started/rate-limits) |
| 502 | `upstream_unavailable` | GitHub did not respond |
| 503 | `temporarily_unavailable` | The endpoint is briefly unavailable. Retry after `details.retry_after` seconds |

## Limits

Only public repositories are supported. GitHub keeps run history for 90 days by default, and repository admins can delete runs, so a clean result covers what is still visible.
